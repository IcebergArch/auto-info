# 系统法则

法则不可违背，只记录宏观约束，不承载具体实现偏好。

1. **规格优先**：需求、用例、契约或系统约束变化必须先更新 `spec/`，再修改实现。
2. **事实可追溯**：auto-info 日报必须以报告形式输出，并包含至少一次真实性/正确性 review 记录。
3. **单一事实源**：项目结构、API 契约、UI 原则、数据存储规范以 `spec/` 为 SSOT。
4. **本地可运行**：MVP 必须能通过 `npm start` 在本地启动，并通过 `npm test` 验证核心用例。
5. **高维变更入规范**：数据库、设计风格、架构边界等项目级决策必须同步写入规范或规则文件。
6. **问题关闭先复盘（P0）**：见 `ISSUE-CLOSURE-REVIEW.md`；规则修订须简洁去重，见 `RULES-MAINTENANCE.md`。
