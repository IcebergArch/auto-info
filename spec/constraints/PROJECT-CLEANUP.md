# 项目清理与收敛规范

## 目标

在保证核心知识与可运行性的前提下，持续清理冗余文件、过时目录和重复实现，保持目录树与当前架构一致。

## 核心保留（不得删除）

- `spec/`：需求、用例、契约、约束（SSOT）
- `services/api/`：后端唯一实现
- `apps/web-react/`：前端唯一实现
- `data/`：本地数据与配置
- `scripts/`：审查与验证脚本
- `docs/architecture/`：系统架构设计文档
- `docs/rules/`：编码规则、团队流程、任务模板
- `docs/iterations/`：迭代计划与执行记录
- `AGENTS.md`、`README.md`、`package.json`

## 清理规则

1. **禁止双份实现**：同一能力不得同时在旧目录与新目录维护。
2. **删除过时目录**：迁移遗留目录（如临时切流目录）在不再使用后立即清理。
3. **归档而非丢弃**：仍有参考价值的系统文档应按域迁入 `docs/architecture/`、`docs/rules/`、`docs/iterations/`，不应散落根目录。
4. **空目录即问题**：无实际文件的目录必须删除。
5. **禁止僵尸文件**：未被引用、无维护价值、与当前架构冲突的文件必须清理。

## 验证门禁

完成清理后必须执行：

```bash
npm run audit
npm run verify
```

涉及功能行为变化时，额外执行：

```bash
npm test
```
