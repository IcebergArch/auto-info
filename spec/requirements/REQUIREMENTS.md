# 需求摘要

## 背景

Nexus Auto-Intel 是本地可运行的信息与研究平台，面向「今日全球重大事件 → 多事件关联分析 → 资料阅读与摘要」三条主路径。

## 功能需求

### REQ-F-001 今日重大事件（UC-001）

用户进入首页应看到低干扰搜索入口与历史记录；进入 auto-info 应能查看 `yyyy-mm-dd` 日报，日报包含**概述、四块正文、参考**，且生成结果必须包含至少一次真实性/正确性 review。日报正文四块为：**国际局势**、**科技**、**金融**、**其他**（医疗/旅行/中国生活/媒体热点等）；不再展示「感兴趣方面」。用户关注类别仍可用于配置与检索，但不参与日报分段。

### REQ-F-005 关注方向管理（UC-001 扩展）

用户可在 auto-info 页面维护自己的关注类别（例如：国际局势、中国政策、AI、音视频），支持新增与删除。关注类别用于 intake 检索与库内匹配（标题、摘要、标签、类目、区域字段）的相关性加权；**不再在日报正文中生成独立的「感兴趣方面」段落**（日报正文固定为国际局势 / 科技 / 金融 / 国内 / 其他，见 REQ-F-001 与 UC-001）。

> 说明：早期版本曾要求「优先在『感兴趣方面』中展示」，已随 UC-001 报告结构收敛而废除，此处与 UC-001 对齐，避免规格冲突。

### REQ-F-002 事件标签关联分析（UC-002）

用户进入**分析** Tab，输入事件主题或选择一个/多个**事件标签**，系统应返回匹配事件及其**关联关系**与**相互影响**描述（图谱结构），并以箭头颜色/粗细表达积极、平淡、消极影响及关联强度。

### REQ-F-003 阅读助手（UC-003）

用户进入**阅读助手**，可提交论文标题、网页链接、PDF 链接、视频链接或正文/文件；系统解析内容（或接受字幕/转写），生成摘要报告，并写入**历史读取列表**。

### REQ-F-004 系统配置与链路状态（UC-004）

用户可通过配置入口管理 MySQL、Neo4j、Google Search、LLM 模型与 key 等信源/服务配置，并看到当前链路是否打通、是否处于本地 JSON 降级。

### REQ-F-006 AI 科技雷达（UC-006）

用户进入**科技雷达** Tab，可查看近期（30 天内）AI 概念、热词与技术论文动态，以及超过 30 天或按月归档的往期综述；条目可关联 UC-003 阅读简报；布局为左主区 8、右侧相关资料 2。

## 非功能需求

- **REQ-NF-001**：系统运行架构为两层：前端 `React + Zustand + ReactFlow`，后端 `Node.js services/api`（唯一后端）。
- **REQ-NF-008**：后端仅提供 `/api/*` 与 `GET /` 健康检查 JSON，不得托管 `apps/web-react` 页面或 `dist` 静态资源（唯一 UI 入口为前端 dev/构建产物）。
- **REQ-NF-002**：事件与阅读记录必须支持持久化；本地 `data/` 可作为开发降级与缓存。
- **REQ-NF-003**：外部链接抓取失败时返回可理解的错误与降级提示。
- **REQ-NF-004**：MySQL 是事件、日报、历史等结构化数据主存储；本地 JSON 仅作为开发降级/缓存。
- **REQ-NF-005**：Neo4j 可作为事件分析图谱存储；不可用时使用内存图谱算法降级。
- **REQ-NF-006**：所有重构任务必须遵循 Product Agent 生命周期并完成最终验收后方可关闭。
- **REQ-NF-007**：系统重构按 10 轮连续迭代推进，每轮都需包含 Design 审查与 Quality 验证。
