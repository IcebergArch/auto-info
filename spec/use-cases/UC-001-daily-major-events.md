# UC-001：查看今日世界重大事件

**Implements:** REQ-F-001  
**Actors:** 用户（主）、事件存储服务（次）  
**Preconditions:** 服务已启动；事件库已初始化（种子或已有数据）  
**Postconditions:** 用户获得指定日期 `yyyy-mm-dd` 的 auto-info 日报，且报告包含至少一次 review 记录  

## 触发

用户打开首页输入事件/公司/国家/主题；或进入 auto-info 查看指定日期日报。

## 首页信息架构（产品迭代）

1. 首页保持 Google 风格：页面主视觉为搜索区 + 主区报告；搜索后进入分析/日报联动。
2. 主区（`home-report-view`）展示**当前选中日期**的日报（默认今日）；`home-search-block` **高度稳定**，报告展开/收起不得导致搜索区变形。
3. **今日日报**（`presentation: timeline`）使用 `DailyReportTimeline`：**概要** → **时间线** → **相关资料**。`EventTimeline`：**垂直 Card** + 左侧时间轴；顶部须有 **「上次更新」截止点**（`00:00 — lastRefreshedAt`），无当日事件时在该节点标注空态；有事件时截止点之下为更早的当日事件节点（倒序）。有时间的条目**按时间倒序**（最新在上）；当日条目展示到 **小时:分钟**；**无 `occurredAt`** 的排在末尾，轴点为 **「当前」**，与上一时间点 **虚线** 相连。分栏 Tab：**国际 / 科技 / 金融 / 国内 / 其他**；时间线仅取自当日 `events`（不得从陈旧 `sections` 混入跨日条目）；弱文案过滤；每 **1 小时**刷新。**历史日报**为 `DailyReportDetail`；标题不可点，仅 ↗。
4. 查看今日时，卡片右上角提供「刷新当日」；查看历史日期时提供「回到今日」。
5. 侧边栏**仅筛选**：日期列表、归档切换与一个「补齐历史」入口；**禁止在侧栏再嵌一份报告正文**；历史补齐表单属于低频批处理能力，必须用弹窗承载按天数/按月/长区间配置、提示与结果，避免常驻挤占日期筛选空间；选中日期后左侧主区加载该日同一套展开模块。
5a. 侧栏日期列表：**置顶固定「今日日报」**（仅指 **产品时区 Asia/Shanghai 当日**，不重复出现在历史列表）；历史项展示 **`yyyy-mm-dd · 名称`**；`title` 在 `date !== 产品今日` 时须为 **`yyyy-mm-dd 日报`**，禁止沿用归档快照里的「今日日报」；**今日日报仅纳入 `occurredAt` 按产品时区换算后与当日同日的 event**，不得回填昨日或近 N 天事件；当日无事件时展示空态概要/时间线，禁止在标题或概要中出现「含 yyyy-mm-dd 至 yyyy-mm-dd 收录」类跨日说明。
5b. 侧栏空态文案仅指**历史归档**（「暂无历史归档（今日日报见下方）」）；连续刷新不得因请求竞态清空列表；**`GET /report` 与 `GET /reports` 只读不写库**；归档仅在 `POST report/update|store|backfill` 等显式写入时进行（写路径原子落盘 + 写锁串行）。
6. 侧边栏提供「历史日报补齐」：支持 **按天数**（最近 N 天，含今日，1～31）与 **按月**（`YYYY-MM`，从该月 1 日至 **min(月末, 产品今日)**，不得生成未来日期日报）；`GET /reports` 与首页历史列表 **不得展示 `date > 产品今日` 的归档**。
7. 回溯执行期间，侧边栏显示进度条与简要进度文案（如 `3/10`）。
8. 回溯期间需记录“当前检索到的资料”：
   - 默认折叠仅显示累计数量；
   - 展开后最多展示 5 条明细；
   - 若超出 5 条，支持在固定高度容器内滚动查看其余记录。
9. 用户从首页输入核心事件（如俄乌冲突、伊朗、欧洲）后，系统优先检索近 3 个月资料；若历史资料缺失，需调用搜索链路补齐后入库。
10. 补齐内容需生成结构化摘要并作为独立消息写入事件库（不可只保留瞬时结果）。
11. 首页是程序员每日情报控制台，不是泛新闻墙；主链优先服务 **AI/科技行业信息** 与 **政治/金融等投资判断信息**，工具类能力（阅读助手、快捷访问、配置）作为支撑入口，不抢占首页主任务。
12. 今日日报必须显式展示来源与刷新状态，禁止把「未拉源」「拉源失败」「筛选为空」统一文案成「暂无事件」。状态语义固定为：
    - `not_fetched`：当前日期尚未执行拉源更新，仅按本地事件库生成。
    - `source_failed`：已尝试拉源，但全部 provider 失败或超时。
    - `filtered_empty`：provider 有返回，但转换/筛选后没有当日有效事件。
    - `ready`：存在当日事件，报告与来源证据可展示。
13. 首页手动「刷新当日」必须默认拉取外部信源（等价于 `pullSources=true`），不得只用本地空库重建日报；仅调试、测试或显式维护场景可传 `pullSources=false`。

## 扩展：输入新事件并按类目整理

1. 用户输入主题，可选指定类目（或自动识别）。
2. 客户端 `POST /api/v1/daily-events/intake`。
3. 若输入包含“最新/今日/近期/进展/新闻/动态/latest/recent”等新鲜度意图，服务端必须先调用已配置的外部信源检索最新报道：优先 Google Search / Brave Search；未配置时使用公开新闻检索降级；检索失败时返回降级状态而不是静默伪造最新消息。
4. 外部检索命中的报道需转换为事件并写入事件库，保留来源标题、URL、发布时间与 provider，用于日报“参考”；正文抽取优先使用 Jina Reader（失败时降级为基础抽取）。
5. 服务端再在库内按类目与关键词检索；外部检索无结果且本地匹配不足时，才写入用户输入的观察条目。
5a. 主题匹配须避免子串误判（如 `AI技术` 不得因英文词内 `ai` 命中 `Ukraine`/`Financial`）；科技类检索不得将纯俄乌战事报道作为首选结果。
6. 返回同类目事件列表、外部检索状态，并写入咨询历史。
7. 前端可在右上角 History 中查看咨询及结果。

## 扩展：生成 auto-info 日报

1. 用户进入 auto-info 视图，选择 `yyyy-mm-dd`。
2. 客户端请求 `GET /api/v1/daily-events/report?date=yyyy-mm-dd`。
3. 系统按日期组织事件，生成**每日一篇**报告结构：概要（简述）+ 四大正文块 + 参考。
4. 概要速览须对齐四块：`国际局势`（今日时间线侧栏为「国际」）、`科技`、`金融`、`国内`；**禁止**模板空话与英文碎片拼接（如 `Take、Future相关报道`）；每条须为可核对**关键信息**（决策/数据/主体动作），来自 `displayTitle` 或决策向 `desc`。
5. 正文五块（`focusSections`，归档体）：`international`、`technology`、`finance`、`domestic`（医疗/旅行/民生/本土热点）、`other`（体育、文娱、气候、产业等杂类）。今日以 `timeline` + `timelineHours` + `relatedMaterials` 为主；跨日归档压缩为 `focusSections`（`presentation: archived`）。
6. 用户关注类别（配置页）仍可用于检索与 intake，但**不得**再在日报正文中生成「感兴趣方面」段落。
7. **关键事件卡片**：每条须含 **`displayTitle`（标题，纯文本不可点）+ `desc`（概述，置于标题下）**；**↗** 为唯一来源跳转入口；`title` 为英文原文时作副标题行；**禁止**空话标题；标题须点明发生了什么；禁止概要速览条出现「国际局势 国际局势：」类标签重复。
8. 系统执行至少一次规则 review，检查日期范围、事件完整度、参考存在性与报告结构。
9. 系统自动归档本次日报结果到 `data/auto-info-reports.json`。
10. 返回带 `review.count >= 1` 的日报。
11. 前端报告体：今日 `概要` → `时间线`（Card + 连接线）→ `相关资料`；历史 `概要` → 国际/科技/金融/国内/其他 → `参考`。

## 扩展：维护关注类别

1. 用户在 auto-info 页面查看当前关注类别列表。
2. 用户可新增自定义关注类别（例如：国际局势、中国政策、AI、音视频）。
3. 用户可删除不再关注的类别。
4. 客户端通过关注类别接口持久化用户偏好。
5. 生成日报时系统读取关注类别，并按类别匹配标题、摘要、标签、类目与区域字段。

## 扩展：三版报告模板迭代

1. 系统提供三版报告模板（`v1`、`v2`、`v3`），同一日期同一批数据可切换不同展示策略。
2. `v1` 强调管理层速读：重点结论、宏观变化、风险提示。
3. `v2` 强调研究分析：脉络拆分、兴趣方向分组、参考依据增强。
4. `v3` 强调行动导向：给出优先级、关注点与后续跟踪建议。
5. 模板切换不得改变事件事实，仅改变信息组织方式与摘要表达层次。

## 扩展：更新某一日日报

1. 用户在 auto-info 视图选择某一日期，点击更新。
2. 客户端请求 `POST /api/v1/daily-events/report/update`，传入 `date=yyyy-mm-dd`。
3. 服务端针对政治、金融、科技三条主线拉取该日期附近的外部信源；不可用时返回 provider 降级状态。
4. 命中的外部来源转换为事件并写入事件库，保留标题、URL、发布时间与 provider。
5. 服务端重新生成该日 `yyyy-mm-dd` 日报并自动归档。
6. 前端展示更新后的日报、参考来源、provider 状态、报告状态与 review；若没有事件，必须能解释属于 `source_failed`、`filtered_empty` 还是 `not_fetched`。

## 扩展：日报区间回溯补齐

1. 用户选择 `start` 与 `end` 日期。
2. 客户端请求 `POST /api/v1/daily-events/report/backfill`，Body 传 `days` + 可选 `to`（默认今日），或 `month: "YYYY-MM"`，或兼容 `from`/`to`。
3. 服务端遍历 `[start, end]` 闭区间内的每一天；默认自动拉取当日消息，补齐事件库。
4. 服务端为区间内每一天生成并归档日报；单次区间最多 31 天。
5. 前端必须展示回溯进度（如 `3/10`），直至完成；完成后再展示汇总结果。
6. 日历切换日报时，应以颜色标记“当日是否已有日报归档”。

## 扩展：删除日报归档

1. 用户在 auto-info 历史中选择某个日报快照。
2. 客户端请求 `DELETE /api/v1/daily-events/reports/:date`。
3. 服务端从 `data/auto-info-reports.json` 删除对应日期快照。
4. 前端刷新日报历史列表。

## 主流程

1. 用户进入页面。
2. 客户端请求 `GET /api/v1/daily-events/today`（或带 `category` / `from` / `to` 的列表接口）。
3. 系统筛选 `occurredAt` 按产品时区换算后落在今日或标记为「重大」/`special` 的事件。
4. 系统按 `severity` 降序、`occurredAt` 降序返回事件及标签。
5. 页面以日报报告呈现概述、事件、参考与 review 状态。

## 异常流

### EXC-1：存储不可用

- **触发：** 读取 `data/auto-info-store.json` 失败  
- **响应：** HTTP 500；前端回退本地样例数据（可选）

### EXC-2：区间内无事件

- **触发：** 筛选结果为空  
- **响应：** HTTP 200，`events: []`，前端展示可解释空状态；不得把未拉源、拉源失败和筛选为空混为同一文案
