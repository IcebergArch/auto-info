# UC-002：事件脉络与交叉影响分析

**Implements:** REQ-F-002  
**Actors:** 用户（主）、事件图谱服务（次）  
**Preconditions:** 事件库中存在带 `tags` 的事件记录  
**Postconditions:** 用户看到输入事件近 3 年核心脉络、分级事件列表及交叉影响分析结果  

## 触发

用户进入**分析** Tab，输入一个事件主题（可选补充另一事件用于交叉影响分析）。

## 主流程

1. 用户进入分析视图。
2. 用户输入主事件主题（如“俄乌冲突”），可选择近 3 年窗口（默认 3 年）。
3. 客户端请求 `GET /api/v1/analysis/analyze?query=俄乌冲突&coreOnly=1`（兼容 `/graph`）；**不再**提供「回溯年数」参数，时间窗由服务端按主题自动推断。
4. 系统通过 **intel 入库**（多轮 `intake` 检索 + 主题种子事件）补齐事件库，并优先写入 MySQL `events` 表。
5. 系统从 MySQL 事件库召回近 3 年候选事件，在内存中构建节点与关系边，**同步写入 Neo4j**（`await saveNeo4jGraph`），写入成功则 `graphSource: "neo4j"`。
6. 若 Neo4j 不可用或写入失败，仍返回内存图谱结果，并设置 `graphSource: "memory"` 与 `neo4j.synced=false`、`neo4j.reason`；MySQL 不可用时降级本地事件库，并按 `core|important|context` 分级（默认仅 `core`）。
7. 系统返回 `eventLines`：**主事件**一条时间轴（本域冲突节点落在主事件 x 轴，hover 看概要）；**影响域**泳道为 **政治、金融、科技** 三维；**`mapLayer.regions`** 可继续按节点 `region` 聚合六大地区强度作为 API 兼容字段，但前端分析页不再展示地区概览列表；**对外影响**从主事件 x 位置向对应泳道绘制带标签箭头；本域冲突不画外溢箭头。
8. 系统返回 `chronology`：含起止时间 `timeRange`、分阶段 `phases`（背景/爆发/核心/变动/进展/近期），历史时期粗粒度、近期细粒度。
9. 系统返回按时间排序的脉络节点、关键节点关系、影响维度（policy/market/risk）与强度。
10. 用户可输入“关注的其他事件”（如“能源价格”），客户端携带 `secondaryQuery` 再次请求。
11. 系统在已有主脉络基础上，返回主事件与次事件之间的交叉影响边及文字说明。
12. 分析页优先展示 **事件脉络时间轴**（主可视化），不再展示“概览 / 地区关联列表 / 维度图层”前置模块；跨线影响以**「箭头 + 文字」列表**补充。图谱边标签**禁止**前缀「共享标签：」，直接展示标签名（如 `地缘、冲突`）。图上箭头短标签（如 `同簇·地缘`），完整说明在 hover 与「跨线影响」列表。
13. 每次成功分析须写入 `data/analysis-history.json` 并返回 `sessionId`。**同主事件、无 `secondaryQuery` 时 upsert 唯一会话**（保留 `createdAt`、更新 `updatedAt` 与完整 `result`）；仅当携带 `secondaryQuery`（如「欧洲」「亚太」「日本」）时另建独立会话（如 `俄乌冲突 × 欧洲`）。历史列表按分析键去重，每键仅保留最新一条。
14. 分析页 **8:2 分栏**：右侧历史记录（LRU 去重）；脉络图工具栏提供「更新事件」重新拉取 intel 并 upsert 当前主题会话。
15. 用户点击脉络节点可查看摘要（渐进披露）；**点击**圆点或下方节点列表项展示事件明细，悬停仅作辅助；**同一时段多点重叠**时一次点击选中整组（图上数字角标 + 上方多卡片 + 列表多项 `is-active` 联动）；再次点击同组取消选中。
15a. 脉络图支持 **Chrome DevTools 网络面板式时间区间**：顶部条带拖拽平移/缩放选区，图表区滚轮缩放；视口外节点隐藏，解决点过密难点。时间条与主图必须共用 `eventLines.timeAxis` 非线性映射，禁止前端再按 `(t-start)/(end-start)` 等比例重算。
16. **事件轴叙述**：展示事件背景、爆发起点与进展终点（如 `2014 背景 → 2022-02 爆发 → 至今`），禁止仅显示固定回溯窗口日期。
16. 理想影响图为左到右时间线：长周期地缘主题（如俄乌）主轨须覆盖 **2014→至今** 关键里程碑（不得仅 2022 与 2026 两端）；轴上标注 **年份刻度**；长冲突采用约 **48% / 52%** 历史/近期轴宽，历史段按年/多年压缩、近期段展开到更细粒度；前端节点、箭头、年份刻度与缩放交互必须保持同一“近细远粗”坐标；事件交叉通过分叉箭头表达。
17. 分析历史侧栏预览须展示 **脉络年跨度 + 主轨节点数**，列表项间距紧凑，避免相邻记录信息断层感。

## 分析主题相关性（强制）

- **脉络图 / `buildGraph` / `eventLines`** 使用 `matchesAnalysisQuery`，不得仅用 `matchesQuery` 或事件 `category`/`tags` 中的泛化词（如单独「地缘」）入选。
- 查询为 **俄乌冲突**（及同义）时：仅当 `title`/`summary` 含俄乌强相关词（乌克兰、俄罗斯、顿巴斯、军援、和谈等）才入选；**排除**仅英国能源/「Comrade Keir」等与俄乌无关条目。
- 查询为 **AI / 人工智能 / AI技术** 等科技主题时：**禁止**俄乌战事、Gripen 军援等纯地缘报道进入脉络；不得用 `dimension=market` 兜底捞取无关高 severity 事件。
- 科技主题脉络**主轨**须纳入 GPT/OpenAI/大模型等锚点事件（含 timeline 中的 GPT 提及）；不得仅落在影响泳道或关联列表而不可见。
- **禁止**将入库占位句（`发布/收录：「…」`）作为脉络节点展示文本；须用 `presentEventForReport` 的 `desc` 或有效 timeline 要点。
- 同一事件在脉络图上 **每泳道至多一个节点**（`occurredAt` 窗口内），避免 timeline「来源」点与摘要点叠成多条无信息节点。

## 异常流

### EXC-1：未输入主事件主题

- **触发：** `query` 为空  
- **响应：** HTTP 400，`error: "请至少输入事件主题"`

### EXC-2：Neo4j 不可用

- **触发：** Neo4j 连接失败 / 未配置鉴权  
- **响应：** HTTP 200，`graphSource: "memory"`，`neo4j.synced: false`，并返回降级图谱结果；分析页须展示图谱来源与 Neo4j 同步状态

### EXC-3：无匹配事件

- **触发：** 无事件匹配主事件主题  
- **响应：** HTTP 200，返回近窗口期高相关候选（或高严重度兜底），并标注 `matchMode: "fallback"`
